1. INTRODUCTION                                 *gloss-introduction*

gloss.nvim keeps a dictionary of the terms, acronyms, and jargon a project
actually uses. Look up the word under the cursor and its definition appears
in a floating window holding a real, editable buffer; if no definition
exists, you can write one on the spot, store it in the project's glossary or
your global dictionary, or [planned] let a pluggable AI provider propose one
from codebase context.

A glossary lives outside the repository by default. Running `:Gloss init -p`
moves it into a `.gloss/` directory as line-based JSON that diffs, merges,
and reviews like any other committed text, so a cloned repository brings its
glossary along with zero setup.

2. QUICKSTART                                   *gloss-quickstart*

Requirements: Neovim 0.11+. The SQLite backend (global dictionary and
out-of-repo stores) additionally needs kkharji/sqlite.lua and libsqlite3;
run |:checkhealth| gloss to verify.

Optionally enable the curated keymaps: >lua

  require("gloss").setup({ keymaps = true })
<
Then, in any project:

1. Put the cursor on a term and press `<leader>gg` (or run |:Gloss|). A known
   term opens its definition; an unknown one opens a prefilled new-entry
   buffer (|gloss-buffer|).
2. Write the definition below the blank line, `:w`, and pick the project or
   global store. Saving to the project scope registers the project
   automatically; `:Gloss init` does it explicitly, `:Gloss init -p` puts
   the glossary in the repository instead.
3. `q` closes the float.

3. COMMANDS                                     *:Gloss*

All functionality is reachable through one command with completed
subcommands. [planned] ones currently report their status.

  :Gloss [lookup] [{term}]                      *:Gloss-lookup*
      Resolve {term} (default: the word under the cursor, or the visual
      selection for multi-word terms) through the store chain
      (|gloss.setup.resolve|) and open its definition. On a miss, the
      |gloss.setup.on_miss| chain runs; the default opens a new-entry
      buffer.

  :Gloss add [{term}]                           *:Gloss-add*
      Open a new-entry buffer; writing it asks project or global.

  :Gloss edit {term}   :Gloss delete {term}     *:Gloss-edit* *:Gloss-delete*
      Direct entry operations, term-completed. Delete confirms first.

  :Gloss list [{query}]                         *:Gloss-list*
      Picker over the current project's entries; the optional query uses
      the same grammar as search (`#tag` filters, fuzzy words). Selecting
      an entry opens it for editing.

  :Gloss search [{query}]                       *:Gloss-search*
      Fuzzy search across every store: the current project, the global
      dictionary, and every registered project, each result labeled with
      its origin. `#tag` tokens filter exactly (case-insensitive); other
      tokens fuzzy-match terms, aliases, expansions, and tags, with plain
      substring hits in definition bodies appended after. Selecting an
      entry offers: edit, copy to another store, move, delete, reveal
      origin. Copy/move to a store that already has the term asks
      overwrite / keep both / cancel ("keep both" saves as "{term}
      (copy)"). Note: without a picker plugin overriding |vim.ui.select|
      there is no live filtering, so pass the query argument; with
      telescope/fzf-lua/mini.pick installed the bare form is fully
      fuzzy-filterable.

  :Gloss init [-p]                              *:Gloss-init*
      Register the project. Bare: create its out-of-repo store (also
      happens implicitly on the first save to the project scope). With -p:
      create the in-repo glossary and fold any existing out-of-repo
      entries into it (the old DB is backed up first). Offers the
      merge=union gitattribute (|gloss-jsonl|). If the registry knows this
      repository under another path (a moved or re-cloned repo), init
      offers to relink instead of creating a second glossary.

  :Gloss deinit                                 *:Gloss-deinit*
      Convert an in-repo glossary back to an out-of-repo store. Never
      deletes anything inside the repository; it prints the removal
      command instead.

  :Gloss projects                               *:Gloss-projects*
      Browse every known project glossary from anywhere: pick a project,
      pick an entry, act on it (same actions as search). Covers the
      current project and all registered out-of-repo projects; other
      repositories' in-repo glossaries live in those repositories.

  :Gloss relink                                 *:Gloss-relink*
      Re-attach a moved or re-cloned repository to its registry entry.
      With a pending remote-matched candidate this confirms it; otherwise
      it offers the registry list to link the current root to.

  :Gloss gc                                     *:Gloss-gc*
      Clean up registry entries whose roots vanished (confirmed, never
      automatic). [planned]

  :Gloss export [{path}]  :Gloss import [{path}]  *:Gloss-export*
      JSONL out of / into the current store. [planned]

  :Gloss ai on|off|status                       *:Gloss-ai*
      Per-project consent gate for sending code context to the configured
      AI provider. Off until explicitly enabled. [planned]

  :Gloss doctor                                 *:Gloss-doctor*
      Report damaged glossary lines, duplicate terms across stores, and
      stale registry paths. [planned]

4. KEYMAPS                                      *gloss-keymaps*

No mappings are installed by default. Every action has a <Plug> mapping;
the opt-in curated set installs under a configurable prefix and never
clobbers an existing mapping (skipped maps are reported once and by
`:checkhealth gloss`).

  <Plug>(GlossLookup)    normal and visual mode lookup
  <Plug>(GlossAdd)       new entry
  <Plug>(GlossSearch)    cross-store search
  <Plug>(GlossList)      current project's entries
  <Plug>(GlossProjects)  projects browser

The curated set (|gloss.setup.keymaps|), default prefix `<leader>g`:
suffix `g` lookup, `a` add, `s` search, `l` list, `p` projects. Each action
takes its own lhs or `false` in the keymaps table.

5. THE DEFINITION BUFFER                        *gloss-buffer*

Definitions open in a floating window holding a real buffer
('buftype' = acwrite, 'filetype' = markdown): edit with everything you own,
`:w` persists, `q` closes (blocked while modified). Add and edit are the
same buffer. The round-trip format is a header block, one blank line, then
the markdown definition: >

  term: DLQ
  expansion: dead letter queue
  aliases: dlqs, dead-letter queue
  tags: aws, queue

  Queue that collects messages which could not be processed.
<
All four header keys are always shown; empty values are fine. Editing the
`term:` line renames the entry on the next write. A new entry asks which
store to save to (project or global) on its first write.

6. CONFIGURATION                                *gloss.setup* *gloss-config*

Calling setup() is optional; everything works with defaults. >lua

  require("gloss").setup({
    project_dir = ".gloss",
    resolve = { "project", "global" },
    on_miss = { "prompt" },
    keymaps = false,
    case = { short_acronym_len = 3 },
    ai = { provider = nil },
    data_dir = nil,
  })
<
                                                *gloss.setup.project_dir*
project_dir       Directory name whose presence at the project root selects
                  in-repo mode. Default: `".gloss"`.

                                                *gloss.setup.resolve*
resolve           Ordered store chain for lookups. List-valued options
                  replace the default entirely rather than merging.
                  Default: `{ "project", "global" }`.

                                                *gloss.setup.on_miss*
on_miss           Ordered fallback chain when no store has the term.
                  Default: `{ "prompt" }`.

                                                *gloss.setup.keymaps*
keymaps           `false` (nothing installed), `true` (curated set under
                  `<leader>g`), or a table with `prefix` plus per-action
                  overrides where each action takes a lhs string or `false`.

                                                *gloss.setup.case*
case              `short_acronym_len`: uppercase terms at or under this
                  length match case-sensitively. Default: 3.

                                                *gloss.setup.ai*
ai                `provider`: a GlossProvider table (|gloss-ai|), or nil to
                  disable the AI miss handler.

                                                *gloss.setup.data_dir*
data_dir          Override where the global dictionary, registry, and
                  out-of-repo project stores live.
                  Default: `stdpath("data") .. "/gloss"`.

==============================================================================
7. STORAGE                                      *gloss-storage* *gloss-jsonl*

Out-of-repo stores and the global dictionary are SQLite databases under
|gloss.setup.data_dir|, WAL mode, safe across concurrent Neovim instances.

In-repo glossaries are JSONL: `.gloss/glossary.jsonl`, one entry per line,
sorted by term, fixed key order, version header on line one. Recommended
gitattribute: >

  .gloss/glossary.jsonl merge=union
<
Damaged lines (bad merges, hand edits) are skipped on load, preserved
verbatim on write, and reported by `:Gloss doctor`.

==============================================================================
8. AI PROVIDERS                                 *gloss-ai* *gloss-provider*

[planned] A provider is a table with a `name` and one function: >lua

  propose(request, callback)
<
`request` carries the term plus context gathered by gloss (surrounding
lines, capped project-wide usages, README head). The callback receives a
table with `definition`, `expansion`, and `confidence`, or `questions` (a
list of clarifying questions gloss relays to the user, one round-trip).
Proposals are never saved automatically; they open in the review buffer
marked as AI-sourced. Providers run only after `:Gloss ai on` in that
project.
